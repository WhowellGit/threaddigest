# The push rule changes on Wes's ruling (2026-09-16)

Record for commit `012b602`. Surface touched: `tools/hooks/no_bypass_git.sh`,
`tests/gates/test_hooks.py`, `CLAUDE.md` — the enforcement surface and the working agreement,
both review-required. Seat: the session that made the change, under a bounded brief. That is
this record's weakness and it is stated here rather than implied: no independent seat read it.

## The ruling

Wes, 2026-09-16, in his own words: "if I tell you to push to main, you should push to main."

## What the rule was, and why it existed

`tools/hooks/no_bypass_git.sh` refused every `git push` whose destination resolved to `main`,
in any spelling, and refused a bare push while the current branch was `main`. It was written on
2026-09-14 (the packet panel's dry run, D-23's neighbourhood in the decisions log), when the
repository had no remote at all. A push then could only be a mistake or an attempt to reach
somewhere the project had not decided to reach.

## Why the refusal no longer earns its place

`make hooks` installs a pre-push stage that runs the whole `make check` (the `make-check` hook
in `.pre-commit-config.yaml`, `stages: [pre-push]`). Every push therefore runs the full gate on
the tree being sent, before a byte leaves the machine. A plain push is not a bypass of the
gate; it is the gate, run once more. A remote is a backup and never the gate, and refusing the
backup does not make the gate stronger.

## Where the new boundary sits

Allowed: a plain `git push` of `main` — by refspec in any spelling (`origin main`,
`HEAD:refs/heads/main`, `feature:refs/heads/main`) or with no refspec while the branch is
`main`.

Refused, each with a message naming the part of the rule it fails:

| Form | Why it is not the plain push |
|---|---|
| `--no-verify` | skips the pre-push check, which is the only reason a push is safe |
| `--all`, `--mirror` | carry every branch, not the one push that was asked for |
| `--force`, `-f`, any short cluster holding `f`, `--force-with-lease` | rewrite `main` on the remote |
| a `+main` refspec | the same rewrite in refspec spelling |
| `--delete`, `-d`, an empty source (`:main`) | remove `main` on the remote |

The line is drawn at what the pre-push check can hold. The check runs on the tree being sent,
so it can vouch for that tree; it cannot see the history the remote already holds, which is
exactly what a force push destroys and what a deletion removes.

## What proves it

`tests/gates/test_hooks.py::test_a_plain_push_to_main_is_allowed_and_every_other_form_is_not`
pairs the four allowed spellings with ten refusals and asserts the reason on each refusal, so a
message rewritten into something vaguer fails the control too; the parametrized `GIT_ROWS` and
the bare-push branch rows carry the same boundary through the tokenizer's paths (indirection, a
trailing comment, a redirection, a backslash-newline continuation, a branch switch earlier in
the command).

Both halves were watched go red before they were trusted: with the force branch of `check_push`
disabled, the control and three bare-push rows failed on `git push --force origin main`
returning 0; with the `--no-verify` branch disabled, the control and two rows failed on
`git push --no-verify origin main` returning 0. The hook was restored and the file's 207
collected cases ran green.

## What an independent seat should attack

1. The force-flag match is textual (`--force*` and a short cluster holding `f`). A spelling that
   force-updates `main` without one of those tokens would pass: the `+` refspec form is covered,
   but a configuration that makes a plain push a force push (`push.default`, a refspec in
   `remote.origin.push`) is not, and this hook does not read git configuration.
2. A bare push whose branch cannot be read is still allowed, as it was before; that fail-open
   predates this change and is unchanged by it.
3. The rule now rests on the pre-push stage being installed. `make check` prints the hooks line
   and `doctor` reports it, but a checkout where `make hooks` never ran has the agent's hook and
   not the gate behind it.
